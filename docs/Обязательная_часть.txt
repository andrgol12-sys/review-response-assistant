Пользователь отправляет отзыв через страницу templates/index.html, а обработчик POST /api/reviews в api/routes.py тестового сайта сохраняет его со статусом new через модель models/review.py и сессию db/session.py; приложение запускается из main.py, настройки берутся из config.py.
В worker.py запускается периодический опрос, при котором client.py получает отзывы через GET /api/reviews и отбирает записи со статусом new, используя структуры из models.py проекта обработчика.
Для каждого пользовательского отзыва worker.py вызывает detect_tone из processor.py: в предоставленном коде тональность определяется по положительным и отрицательным маркерам, а не нейросетью.
Затем telegram_bot.py пытается отправить уведомление о новом отзыве и его тоне в Telegram, если заданы токен и chat_id, а успешная отправка отмечается через state.py.
После проверки локального состояния worker.py вызывает generate_response из processor.py, который при наличии ключа обращается к OpenAI API, а без ключа возвращает локальный шаблонный ответ.
Через client.py обработчик публикует ответ отдельной записью с parent_id исходного отзыва, обновляет тон исходного отзыва и переводит обе записи в processed; собственные сообщения AI Support обрабатываются без создания нового ответа.
Файл состояния JSON, с которым работает state.py, сохраняет идентификаторы обработанных отзывов и отметки уведомлений между запусками, поэтому вместе с фильтрацией статуса на сайте помогает избежать повторных ответов и уведомлений при обычном повторном опросе, хотя не гарантирует отсутствие дублей при сбое между сетевыми запросами и сохранением состояния.
